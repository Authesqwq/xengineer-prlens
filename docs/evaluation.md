# PRLens 评测体系

## 1. 评测目标

验证 PRLens 在以下方面的表现：
- 变更总结是否准确、可读
- 风险识别是否覆盖目标类型且依据充分
- Review 建议是否具体、可操作
- 输出结构是否稳定、可解析
- 在边界和对抗场景下是否保持克制

## 2. 评测场景

| 场景 | 说明 |
|---|---|
| 正常小型 PR | diff 较短，文件数量少 |
| 多文件 PR | 涉及多个模块 |
| 测试缺失 PR | 修改业务逻辑但未修改测试 |
| 描述不足 PR | PR body 为空或说明过短 |
| 长 diff PR | 需要截断处理 |
| 低风险 PR | 不应强行生成严重问题 |
| 安全敏感 PR | 涉及 token、权限、输入解析 |
| 非法链接 | 链接格式错误或不是 PR 链接 |

## 3. 评分维度

| 维度 | 权重 |
|---|---|
| 变更理解准确性 | 25% |
| 风险识别有效性 | 30% |
| 依据可追溯性 | 20% |
| 建议可执行性 | 15% |
| 输出格式稳定性 | 10% |

## 4. MVP 阶段达标标准

- 综合得分 >= 3.5 / 5
- 输出必须包含依据
- 不强制生成风险
- 不输出无依据的确定性结论
- 输出结构需要稳定
- 安全合规问题一票否决

## 5. Bad Case 记录模板

每条 bad case 至少记录：

- 来源（用户反馈 / 自测 / 评测集）
- 场景层级（核心 / 边界 / 对抗 / 安全）
- 失败类型（幻觉 / 误报 / 漏报 / 格式 / 表达）
- 输入概要
- 实际输出
- 期望输出
- prompt 版本
- 模型版本
- 根因分析
- 改进方向

## 6. 后续维护机制

1. 每周将误报、漏报和格式失败样本回流到 `eval/bad_cases.jsonl`
2. 每次新增功能场景，同步补充对应评测用例
3. 每个评测样本记录来源、场景层级、期望输出、prompt 版本和模型版本
4. 每季度清理过时样本
5. prompt 或模型变化后跑评测集回归
